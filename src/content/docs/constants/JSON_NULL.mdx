<LSLConstant name="JSON_NULL" />

Return value for [llJsonValueType](/functions/llJsonValueType/) function indicating the Json data type of a given address specifier in a given string-serialized JSON text.

Also the return string value for [llJsonGetValue](/functions/llJsonGetValue/) function when the bare word 'null' is at the given address specifier in a given string-serialized JSON text.

Also used to encode the bare word 'null' within a Json text to signify an empty, valueless placeholder Value at that location (the empty LSL String, "", can be used as well for that).

## Examples

<details open>
<summary>Example 1</summary>

```lsl collapse={4-8}
// Showing usage of JSON_NULL
// within a Json text string
string jText;

default
{
    state_entry(){
        jText = llList2Json(JSON_OBJECT, ["A", 4, "B", 5]);
        llOwnerSay(jText); // jText is '{"A":4,"B":5}'
        llOwnerSay(llJsonGetValue(jText, ["B"])); // The string "5"
        jText = llJsonSetValue(jText, ["B"], JSON_NULL);
        llOwnerSay(jText); // jText is now '{"A":4,"B":null}'
        llOwnerSay(llJsonGetValue(jText, ["B"])); // The Unicode value of JSON_NULL

        }
}
```

</details>

## Known issues

From the issue templates included by the wiki article:

- BUG-3692: type=bug|&lt;s>JSON_NULL may be deceptively returned instead of JSON_INVALID when \[http://tools.ietf.org/html/rfc4627 noncompliant Json text\] is encountered by either llJsonValueType or llJsonGetValue.&lt;/s> Fixed with release 13.09.21.281328.

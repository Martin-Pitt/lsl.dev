<LSLConstant name="PRIM_TYPE" description />

Gets or sets the `type_flag` of the prim and associated type `type_parameters`.

## Usage

### \[ [PRIM_TYPE](/constants/PRIM_TYPE/), [integer](https://wiki.secondlife.com/wiki/integer) **flag** \] + **flag_parameters**

- [integer](https://wiki.secondlife.com/wiki/integer) **flag** — PRIM_TYPE\_\* flag

Used with [llSetPrimitiveParams](https://wiki.secondlife.com/wiki/LlSetPrimitiveParams) & [llSetLinkPrimitiveParams](https://wiki.secondlife.com/wiki/LlSetPrimitiveParams#llSetLinkPrimitiveParams).

The values needed for **type_parameters** is dependent on **type_flag**, please refer to the individual PRIM_TYPE\_\* articles for additional information.

#### Caveats

- [PRIM_TYPE](/constants/PRIM_TYPE/) can only be used with [LINK_SET](/constants/LINK_SET/) if the object contains 10 or fewer prims. It can only be used with [LINK_ALL_OTHERS](/constants/LINK_ALL_OTHERS/) or [LINK_ALL_CHILDREN](/constants/LINK_ALL_CHILDREN/) if the object contains 11 or fewer prims. If there are more prims, the operation will fail and an error will be shouted to [DEBUG_CHANNEL](/constants/DEBUG_CHANNEL/). Work around this by looping through the prims with [llSetLinkPrimitiveParamsFast](/functions/llSetLinkPrimitiveParamsFast/).
- [PRIM_TYPE](/constants/PRIM_TYPE/) will silently fail when executed by a script placed inside a mesh, whether the affect object is the mesh or not (in linksets for example), use a normal prim as your root prim.

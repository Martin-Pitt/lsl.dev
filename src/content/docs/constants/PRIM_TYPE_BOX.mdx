`PRIM_TYPE_BOX` is a parameter of [PRIM_TYPE](/constants/PRIM_TYPE/) used to make prim into a box and to change specific properties that define the shape of that box.

## Usage

### \[ [PRIM_TYPE](/constants/PRIM_TYPE/), [PRIM_TYPE_BOX](/constants/PRIM_TYPE_BOX/), [integer](https://wiki.secondlife.com/wiki/integer) **hole_shape**, [vector](https://wiki.secondlife.com/wiki/vector) **cut**, [float](https://wiki.secondlife.com/wiki/float) **hollow**, [vector](https://wiki.secondlife.com/wiki/vector) **twist**, [vector](https://wiki.secondlife.com/wiki/vector) **top_size**, [vector](https://wiki.secondlife.com/wiki/vector) **top_shear** \]

- [integer](https://wiki.secondlife.com/wiki/integer) **hole_shape** — PRIM_HOLE\_\* flag
- [vector](https://wiki.secondlife.com/wiki/vector) **cut** — x and y range from 0.0 to 1.0, x must be at least 0.05 smaller than y (z is ignored)
- [float](https://wiki.secondlife.com/wiki/float) **hollow** — ranges from 0.0 (solid) to 0.95 (maximum hollowed)
- [vector](https://wiki.secondlife.com/wiki/vector) **twist** — ranges from -1.0 (-180 degree in the edit window) to 1.0 (+180 degree in the edit window) for both x and y (z is ignored)
- [vector](https://wiki.secondlife.com/wiki/vector) **top_size** — ranges from 0.0 to 1.0 to 2.0 for both x and y (z is ignored)[!](#z-taper)
- [vector](https://wiki.secondlife.com/wiki/vector) **top_shear** — ranges from -0.5 to 0.5 for both x and y (z is ignored)

| Constant | Type | Value | Description |
| --- | --- | --- | --- |
| [PRIM_HOLE_DEFAULT](/constants/PRIM_HOLE_DEFAULT/) | integer | `hex=0x00` | Default |
| [PRIM_HOLE_SQUARE](/constants/PRIM_HOLE_SQUARE/) | integer | `hex=0x20` | Square |
| [PRIM_HOLE_CIRCLE](/constants/PRIM_HOLE_CIRCLE/) | integer | `hex=0x10` | Circle |
| [PRIM_HOLE_TRIANGLE](/constants/PRIM_HOLE_TRIANGLE/) | integer | `hex=0x30` | Triangle |

### \[ 1, [PRIM_TYPE_BOX](/constants/PRIM_TYPE_BOX/), [vector](https://wiki.secondlife.com/wiki/vector) **cut**, [float](https://wiki.secondlife.com/wiki/float) **hollow**, [float](https://wiki.secondlife.com/wiki/float) **twist**, [vector](https://wiki.secondlife.com/wiki/vector) **top_size**, [vector](https://wiki.secondlife.com/wiki/vector) **top_shear** \]

- [vector](https://wiki.secondlife.com/wiki/vector) **cut** — x and y range from 0.0 to 1.0, x must be at least 0.05 smaller than y (z is ignored)
- [float](https://wiki.secondlife.com/wiki/float) **hollow** — ranges from 0.0 (solid) to 0.95 (maximum hollowed)
- [float](https://wiki.secondlife.com/wiki/float) **twist** — ranges from -0.5 (-180 degree in the edit window) to 0.5 (+180 degree in the edit window)
- [vector](https://wiki.secondlife.com/wiki/vector) **top_size** — ranges from 0.0 to 1.0 for both x and y (z is ignored)[!](#z-taper)
- [vector](https://wiki.secondlife.com/wiki/vector) **top_shear** — ranges from -0.5 to 0.5 for both x and y (z is ignored)

This is the old [PRIM_TYPE](/constants/PRIM_TYPE/) format for boxes ([PRIM_TYPE](/constants/PRIM_TYPE/) used to be 1 instead of 9). Use the new format unless you are maintaining old code.

## Caveats

- **z_taper** and client values are different, the ranges do not line up, conversion is required. This simple equation can be used: `answer = 1.0 - value`. See [top_size Explained](#top-size-explained) for more information.

## Examples

<details open>
<summary>Example 1</summary>

```lsl
llSetPrimitiveParams([PRIM_TYPE,
                        PRIM_TYPE_BOX,
                            PRIM_HOLE_DEFAULT,  // hole_shape
                            <0.00, 1.0, 0.0>,   // cut
                            0.0,                // hollow
                            <0.0, 0.0, 0.0>,    // twist
                            <1.0, 1.0, 0.0>,    // top_size
                            <0.0, 0.0, 0.0>     // top_Shear
                      ]);
```

</details>

When the original [PRIM_TYPE](/constants/PRIM_TYPE/) interface was retired ([PRIM_TYPE_LEGACY](#prim-type-legacy), [SL 1.5](http://secondlife.wikia.com/wiki/Version_1.5)), the new [PRIM_TYPE](/constants/PRIM_TYPE/) interface did not yet support tapering of the bottom of the prim, this feature wasn't added until [SL 1.11](http://secondlife.wikia.com/wiki/Version_1.11) (two years later). Instead of retiring the new [PRIM_TYPE](/constants/PRIM_TYPE/) when it was added, the range of **top_size** was enlarged; meanwhile in the client they redefined the parameter and it's values. This redefinition and range enlargement resulted in two interfaces that did the same thing but achieved it through different values. Meanwhile [PRIM_TYPE_LEGACY](#prim-type-legacy)'s interface was not updated to support tapering of the bottom of the prim. Consequently all three interfaces have different ranges, making for a rather nasty caveat.

Users interact with objects by clicking them, and with scripted vehicles, weapons and HUDs through captured controls. A script can capture movement keys and the mouse button, and read game control buttons and axes from a controller, or from the keyboard and mouse translated by the viewer.

Input is not free text: for choices and typed input, use [dialogs](/features/communications/dialog/), text boxes or [chat commands](/features/communications/).

Touch needs no permission. Controls need [`PERMISSION_TAKE_CONTROLS`](/constants/PERMISSION_TAKE_CONTROLS/); game control needs [`PERMISSION_GAME_CONTROL`](/constants/PERMISSION_GAME_CONTROL/) and viewer support.

<Column>
<Box title="Concepts">

- Clicking an object raises [touch events](/features/input/touch/), with [who touched](/functions/llDetectedKey/), [which prim](/functions/llDetectedLinkNumber/) and [where](/functions/llDetectedTouchST/) read by the detected functions
  - A [click action](/functions/llSetClickAction/) changes what a left-click does
- Scripts can [capture](/features/input/controls/) movement keys and the left mouse button
  - Needs [permission](/functions/llRequestPermissions/) from the avatar, granted in [`run_time_permissions`](/events/run_time_permissions/)
  - The [`control`](/events/control/) event reports which keys are held and which changed
  - Controls can also pass through to normal movement
  - Sitting avatars can be [forced into mouselook](/functions/llForceMouselook/), and [agent info](/functions/llGetAgentInfo/) tells whether an avatar is [in mouselook](/constants/AGENT_MOUSELOOK/)
- [Game control](/features/input/game-control/) buttons and axes, from a controller or translated keyboard and mouse, arrive in [`game_control`](/events/game_control/), for scripts in attachments or seats

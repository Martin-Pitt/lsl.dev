The full list of viewer URI forms, from the Second Life Wiki's [Viewer URI Name Space](https://wiki.secondlife.com/wiki/Viewer_URI_Name_Space) page (revision 1219168, 6 October 2026), with the wording as written. Numbers in parentheses, such as (2.0), are the viewer version the wiki gives for a form. Part of the [Viewer URIs](/features/viewer-uris/) feature.

## Overview

The SL client supports [links](https://en.wikipedia.org/wiki/URI) of the format `secondlife://Region/123/45/67/<region name>`, which have traditionally specified a region name and `x/y/z` location. This means "run Second Life viewer and show Region on the world map".

The new [URL scheme](https://en.wikipedia.org/wiki/URI) has 3 slashes[^rfc3986], and allows direct control of the user interface and login. For example, `secondlife:///app/login`

Most `secondlife:///app` URLs only work from browser instances running inside Second Life because of a denial-of-service attack using `secondlife:///app/teleport` links to force repeated teleports. [SLURL](https://wiki.secondlife.com/wiki/SLURL)s that work with external browsers include:

- `secondlife://<region name>`
- `secondlife:///app/login`

In chat, dialogs and other user interface elements, these URLs will be highlighted as clickable links, often with custom formatting including icons. The full functionality is available in Viewer 2.0 and up. Clickable links without formatting were available only in older versions' chat and [IM](https://wiki.secondlife.com/wiki/Instant_Message) history.

These links also may be known as *Viewer URL Namespace*, *SLAPP URLs* or *Application [SLURL](https://wiki.secondlife.com/wiki/SLURL)*.

## Syntax

Each row shows the URI up to the part it describes. Parts in angle brackets are parameters.

### Region locations

| URI | Description |
| --- | --- |
| `secondlife://<region_name>` | log in to this region or, if logged in, show information and offer teleport |
| `secondlife://<region_name>/<local_x>` | optional X position, defaults to 128 |
| `secondlife://<region_name>/<local_x>/<local_y>` | optional Y position, defaults to 128 |
| `secondlife://<region_name>/<local_x>/<local_y>/<local_z>` | optional Z position, defaults to 0 |

## Second Life Wiki formatting

When adding `secondlife://` links using the above syntax to a Second Life Wiki page, you can enclose your links in squared brackets (thus turning them into a standard Wiki external link), which also gives you the chance of changing the displayed text. Example:

```text
[secondlife:///app/objectim/190f571d-fdf1-8f6c-4e9d-973e9b5e0566?name=ObjectName&owner=c93c3129-2250-4c79-a5f7-8c755ca2707e&groupowned=true&slurl=Location/128/128/27 ObjectName]
```

will display as a link labelled "ObjectName".

In this case you will also need to ensure the object name has been escaped.

Sometimes, having the link clickable (which will attempt to launch the Second Life Viewer to open it), is not desirable. Instead, to display the [URI](https://en.wikipedia.org/wiki/URI) itself without making it clickable, surround it with `<nowiki>...</nowiki>`. For example:

```text
<nowiki>secondlife:///app/group/8db35111-979b-14a7-6a74-b47be86ce04f/about</nowiki>
```

will display as `secondlife:///app/group/8db35111-979b-14a7-6a74-b47be86ce04f/about` (not clickable), whereas

```text
secondlife:///app/group/8db35111-979b-14a7-6a74-b47be86ce04f/about
```

will display the whole link and make it clickable.

## LSL Examples

```lsl
string Who(key id)
{
    return "secondlife:///app/agent/" + (string)id + "/inspect";
}

default
{
    touch_start(integer num)
    {
        llSay(0, "Touched by " + Who(llDetectedKey(0)) + "." );
    }
}
```

[^rfc3986]: Two slashes for the beginning of the authority section — for HTTP requests, this is the name of the server (optionally with the port) — here it's empty; followed by a third slash, terminating the authority section. See [https://www.rfc-editor.org/rfc/rfc3986#section-3.2](https://www.rfc-editor.org/rfc/rfc3986#section-3.2) . Because Second Life is omitting the 'authority' part, that section is empty, thus the three slashes; note that Second Life is *not* the only example of an 'authorityless' communications protocol; there are plenty of other examples.

[^public-channel]: The public (chat) channel, also written as [`PUBLIC_CHANNEL`](/constants/PUBLIC_CHANNEL/)

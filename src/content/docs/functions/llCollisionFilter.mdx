<LSLFunction name="llCollisionFilter" />

Sets the collision filter, exclusively or inclusively.

If **accept** == [TRUE](/constants/TRUE/), only accept collisions with objects **name** AND **id** (either is optional), otherwise with objects not **name** AND **id**

If **name** or **id** are blank they are not used to filter incoming messages (or you could say they match everything).

If **id** is an invalid key or a [null key](/constants/NULL_KEY/), it is considered blank.

```lsl title="How to use" frame="terminal"
llCollisionFilter("", NULL_KEY, 0);
```

## Caveats

- Any call of `llCollisionFilter` in the same event as [llVolumeDetect](/functions/llVolumeDetect/) changing (not just being called, but actually moving from [FALSE](/constants/FALSE/) to [TRUE](/constants/TRUE/) or vice versa) will be disregarded (before or after), **if** the event handler previously called a user-defined function. See [svc 2490](#svc-2490)
- You can get around this by calling them in separate events, such as [touch_start](/events/touch_start/) and [touch_end](/events/touch_end/).
- Damage caused by [llSetDamage](/functions/llSetDamage/) will still apply to a filtered avatar.
- Consequently, the object will immediately die on collision with the avatar. (And kill the avatar their health reaches 0.)

## Examples

<details open>
<summary>Example 1</summary>

- Stop filtering:

```lsl
llCollisionFilter("", NULL_KEY, TRUE);
```

</details>

<details>
<summary>Example 2</summary>

- Filter out all collisions:

```lsl
llCollisionFilter("", NULL_KEY, FALSE);
```

</details>

<details>
<summary>This script, placed in a wearable object, detects a collision when the person wearing it collides with an object named "Post":</summary>

- 1st instance :

an object named "Post" has several child prims named "Object" .

The prim named "Post" hits the scripted object or scripted prim , the collision will be detected

- 2nd instance :

an object named "Post" has several child prims named "Object" .

A child prim named "Object" hits the scripted object or scripted prim, the collision will be detected

- 3rd instance :

an object named "Object" has several child prims named "Post" .

A prim named "Post" hits the scripted object or scripted prim, the collision will not be detected

```lsl
default
{
    state_entry()
    {
        llCollisionFilter("Post","",TRUE);
    }

    collision_start(integer total_number)
    {
        llSay(0, "OUCH!");
    }
}
```

</details>

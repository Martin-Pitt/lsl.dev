<LSLFunction name="llMapBeacon" description />

Asks the viewer to create a beacon for the user and optionally opens the world map centered on the location.

```lsl title="How to use" frame="terminal"
llMapBeacon("", ZERO_VECTOR, []);
```

## Specification

<ConstantGroup name="MapBeaconParam" />

Requests that a user's viewer set a beacon in the world and optionally opens the world map centered on the specified location.

| Constant | Type | Value | Description |
| --- | --- | --- | --- |
| [BEACON_MAP](/constants/BEACON_MAP/) | integer | `1` |  |

## Caveats

- Since this function requests the client to perform a task, there is no way for script to know if it has failed.

## Examples

<details open>
<summary>The following example mimics the behavior of [llMapDestination](/functions/llMapDestination/).</summary>

```lsl
default
{
    touch_start(integer total_number)
    {
        llMapBeacon("WindSong", <185,140,29>, [BEACON_MAP, TRUE, TRUE]);
    }
}
```

</details>

## Notes

- **pos** will work with [Region](https://wiki.secondlife.com/wiki/Viewer_coordinate_frames#region) coordinates not inside `simname`. (like those returned by [llRequestInventoryData](/functions/llRequestInventoryData/))
- if called from non [touch](/categories/touch/) events, it only works for the [owner](https://wiki.secondlife.com/wiki/Category:LSL_Owner).
- if called from touch, it may only work for the first or last touch in the event queue (example: `num_touched > 1`)
- if called inside an [attachment](https://wiki.secondlife.com/wiki/Attachment), it only works for the owner.

## Known issues

From the issue templates included by the wiki article:

- SVC-3455 (bug): llMapDestination ignores look_at parameter
- SVC-1038 (fs): Throttle llMapDestination to prevent "map bombing".
- SVC-1795 (bug): llMapDestination in attachments opens a map on owner's screen even when touched by someone else
- VWR-2060 (bug): llMapDestination **pos** parameter is sometimes replaced with incorrect data (workaround included)
- VWR-7331 (bug): height in **pos** is capped to 1000m (code patch included)

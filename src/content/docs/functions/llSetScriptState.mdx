<LSLFunction name="llSetScriptState" description />

Set the running state of the script `name`.

```lsl title="How to use" frame="terminal"
llSetScriptState("", 0);
```

## Caveats

- Cannot be used to restart a script that has encountered a [run-time error](https://wiki.secondlife.com/wiki/Category:LSL_Error).
- Cannot be used to start a script that has been added via [llGiveInventory](/functions/llGiveInventory/). Scripts sent via [llRemoteLoadScriptPin](/functions/llRemoteLoadScriptPin/), and which have the running state set [FALSE](/constants/FALSE/) by that command, may be started.
- The script appears to stop when its time slice ends, not sooner. If a script tries to stop itself then some LSL code following the `llSetScriptState` call may be executed before the script stops.
- If a script is paused by `llSetScriptState` and is then either re-rezzed, in a region during a restart, or moved into a different region, the script's memory is reset.

## Examples

<details open>
<summary>Example 1</summary>

```lsl
//Stops the Script, at some non-deterministic time later, until invoked with TRUE, in another script
llSetScriptState(llGetScriptName(),FALSE);
// Stall until end of time slice
llSleep(0.1);
```

</details>

<details>
<summary>Example 2</summary>

```lsl
//Starts Another Script
llSetScriptState("somescript",TRUE);
```

</details>

## Known issues

From the issue templates included by the wiki article:

- SVC-1853 (bug): Scripts deactivated by llSetScriptState are reset when the region is reset, when they are taken into inventory and re-rezzed and when crossing sim boundaries.

<LSLFunction name="llSetStatus" />

Sets the object status attributes indicated in the **status**\} mask to **value**

```lsl title="How to use" frame="terminal"
llSetStatus(0, 0);
```

## Caveats

- Status is an object attribute; all prims in an object share the same status.
- Except for [STATUS_BLOCK_GRAB](/constants/STATUS_BLOCK_GRAB/), this only affects the prim the script is in, child prims in linked objects will not be affected.
- Use [STATUS_BLOCK_GRAB_OBJECT](/constants/STATUS_BLOCK_GRAB_OBJECT/) to block grabbing of a link_set.
- Setting [STATUS_PHYSICS](/constants/STATUS_PHYSICS/) fails silently in attached objects. ~ [svc 6549](#svc-6549)
- The [STATUS_ROTATE_X](/constants/STATUS_ROTATE_X/), [STATUS_ROTATE_Y](/constants/STATUS_ROTATE_Y/) and [STATUS_ROTATE_Z](/constants/STATUS_ROTATE_Z/) flags all require that the object first be made physical to have any effect.

## Examples

<details open>
<summary>Example 1</summary>

```lsl
default
{
    state_entry()
    {
        llSetStatus( STATUS_DIE_AT_EDGE | STATUS_PHYSICS, TRUE);
        llSetStatus( STATUS_ROTATE_X | STATUS_ROTATE_Y, FALSE);
    }
}
```

</details>

## Known issues

From the issue templates included by the wiki article:

- SVC-6549 (bug): llSetStatus can't change STATUS_PHYSICS of an attachment despite the status being preserved between attach & drop
- SVC-5531 (bug): llGetStatus(STATUS_ROTATE_Z); will not work on child prims on freshly rezzed objects.
- SVC-1773 (bug): STATUS_BLOCK_GRAB only affects individual prims in a linkset
- SVC-4197 (fs): Create STATUS_TRANSLATE\_\* flags for llSetStatus
- SVC-5723 (fs): New constant STATUS_BLOCK_SIT
- SCR-203 (nf): &lt;code>STATUS_PARCEL_BOUND&lt;/code> status to prevent a physical object from being able to leave the bounds of the current parcel.

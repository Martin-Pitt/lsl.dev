[`llSetText`](/functions/llSetText/) sets a prim's floating text: a block of text that hovers
above the prim, faces the camera and shows through walls. It is a prim property, not a script
effect: the text stays after the script is removed, and only another `llSetText` or
[`PRIM_TEXT`](/constants/PRIM_TEXT/) changes it.

</Prerequisites>

<Requires land="build" />

<Steps>
<BuildStep title="Rez a prim">
Any prim works. The text hangs above the prim's centre, so a tall prim puts the label higher.
</BuildStep>
<BuildStep title="Add the script">
Drop this script in. It labels the prim and counts touches, updating the text on each one.

<ScriptFile name="floating-text.lsl" in="The prim">
```lsl title="floating-text.lsl"
integer touches;

show()
{
    // A space on the blank line keeps it; an empty line would be dropped
    llSetText("Touch me\n \nTouches: " + (string)touches, <1.0, 1.0, 1.0>, 1.0);
}

default
{
    state_entry()
    {
        show();
    }

    touch_start(integer n)
    {
        ++touches;
        show();
    }
}
```
</ScriptFile>
</BuildStep>
</Steps>

The colour is an RGB vector with each component 0.0 to 1.0; alpha 1.0 is opaque and 0.0 is
invisible. The text is at most <Limit id="building-length-hovertext" /> and is truncated beyond
that.

## Removing the text

Set an empty string. The colour and alpha arguments don't matter: the viewer drops the text as
soon as the string is empty.[^v1]

```lsl
llSetText("", ZERO_VECTOR, 0.0);
```

Because the text outlives the script, a label set by a script that was later deleted stays until
something clears it. Dropping this one-shot script in a prim clears it and then removes itself:

```lsl
default
{
    state_entry()
    {
        llSetText("", ZERO_VECTOR, 0.0);
        llRemoveInventory(llGetScriptName());
    }
}
```

To clear text on other prims of a linkset, use
[`llSetLinkPrimitiveParamsFast`](/functions/llSetLinkPrimitiveParamsFast/) with
[`PRIM_TEXT`](/constants/PRIM_TEXT/), for example
`llSetLinkPrimitiveParamsFast(LINK_SET, [PRIM_TEXT, "", ZERO_VECTOR, 0.0])`.

## Lines and layout

- `\n` starts a new line. Lines are centred under each other
- Empty lines are dropped: the viewer splits the text on line breaks and discards empty pieces,
  so `"A\n\nB"` shows as two lines, not three. To keep a gap, put a space on the line (`"A\n \nB"`).
  The same applies at the end: trailing `\n` do nothing, `"\n "` adds a blank line[^v2]
- A long line wraps at a fixed pixel width (1000 px in the current viewer), at a word boundary
  where it can, so one line of your text can show as two[^v3]
- The font is the viewer's own sans-serif UI font; neither font nor size can be set from LSL[^v4]
- Nothing in LSL positions the text. The viewer places it 0.6 × the prim's Z size above the
  prim's centre, straight up in world axes regardless of the prim's rotation. The block's bottom
  edge sits at that point, so adding lines pushes the first line higher, not the last one
  lower.[^v5] To move a label, move or resize the prim, or put the text on a
  transparent child prim where you want it

## How far away it shows

Visibility is decided by each viewer, not the simulator: what you set is the same for everyone,
what they see depends on distance and their settings. Figures below are the Linden viewer's:

- The text starts fading at 8 m and is gone at 12 m, measured after the viewer pulls the text's
  position toward the camera by the prim's bounding radius, so roughly from the prim's bounding
  sphere. That is why a bigger prim's text can be read from further away[^v6]
- Independently of the fade, text whose anchor point (the spot above the prim where it hangs,
  without the bounding-radius pull-in) is more than a set distance from the camera is not drawn
  at all. The default is 64 m (setting `PrimTextMaxDrawDistance`, which users can change; the
  viewer clamps it to 0 to 300 m).[^v7] A huge prim therefore doesn't give you unlimited range
- Text whose alpha after fading is below 0.01 is not drawn. An alpha of 0.0 with a non-empty
  string is a valid way to hide text while keeping it set, but values just above zero look the
  same as hidden[^v8]
- Text on attachments worn by an avatar the user has blocked is hidden. Blocking does not hide
  text on that avatar's rezzed objects[^v9]

## Text on a HUD

Floating text on a HUD attachment is drawn in the HUD layer and is always visible: no distance
fade and no draw-distance cutoff.[^v10] The text still sits 0.6 × the prim's Z size above the
prim, so leave room above a HUD prim on screen.
